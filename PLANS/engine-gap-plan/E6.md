## Step E6.1 — isBlocked(): word-boundary-aware matching

**Problem:** `isBlocked()` uses `prog.find(entry)` which matches `konsole`
inside `konsoleboard`. Legitimate apps with names that contain a blocked
app name as a substring would be incorrectly blocked.

**File:** `fcitx5-engine/src/xtype.cpp`

Current implementation:

```cpp
bool XTypeEngine::isBlocked(const std::string &program) const {
    std::string prog_lower = program;
    std::transform(prog_lower.begin(), prog_lower.end(), prog_lower.begin(), ::tolower);
    for (const auto &app : _cfg.behaviour.blocklist_apps)
        if (prog_lower.find(app) != std::string::npos) return true;
    return false;
}
```

Replace with a function that also checks for word boundaries (`.` is the
separator in reverse-domain-name program names like
`org.kde.konsole`):

```cpp
bool XTypeEngine::isBlocked(const std::string &program) const {
    std::string prog_lower = program;
    std::transform(prog_lower.begin(), prog_lower.end(), prog_lower.begin(), ::tolower);

    for (const auto &entry : _cfg.behaviour.blocklist_apps) {
        if (entry.empty()) continue;

        // Check if entry appears as a complete "component" in the program name.
        // Components are delimited by '.', '-', '_', or string start/end.
        // This allows "konsole" to match "org.kde.konsole" and "konsole"
        // but NOT "konsoleboard".
        auto pos = prog_lower.find(entry);
        while (pos != std::string::npos) {
            bool startOk = (pos == 0) || !std::isalnum((unsigned char)prog_lower[pos - 1]);
            bool endOk   = (pos + entry.size() == prog_lower.size())
                         || !std::isalnum((unsigned char)prog_lower[pos + entry.size()]);
            if (startOk && endOk) return true;
            pos = prog_lower.find(entry, pos + 1);
        }
    }
    return false;
}
```

**Unit tests:** Add to the engine tests (new
`fcitx5-engine/tests/test_xtype_helpers.cpp` or inline in
`test_config_loader.cpp`):

```cpp
// Helper: test isBlocked logic isolated (without a full engine instance).
// Option: expose the boundary-check as a free function in a small util header
// and test it directly. Or test via a thin wrapper.

// Easiest: write a standalone free function matching the same logic:
static bool blockedBy(const std::string& prog, const std::vector<std::string>& list) {
    std::string p = prog;
    std::transform(p.begin(), p.end(), p.begin(), ::tolower);
    for (const auto& entry : list) {
        if (entry.empty()) continue;
        auto pos = p.find(entry);
        while (pos != std::string::npos) {
            bool s = (pos == 0) || !std::isalnum((unsigned char)p[pos - 1]);
            bool e = (pos + entry.size() == p.size())
                  || !std::isalnum((unsigned char)p[pos + entry.size()]);
            if (s && e) return true;
            pos = p.find(entry, pos + 1);
        }
    }
    return false;
}

TEST_CASE("isBlocked word-boundary: konsole blocks konsole and org.kde.konsole") {

    CHECK(blockedBy("konsole",        list));

    CHECK(!blockedBy("konsoleboard",  list));
    CHECK(!blockedBy("mykonsoleapp",  list));
}

    // Note: if users want to block keepassxc-browser too, they add it explicitly.
}
```

## Step E6.2 — Typed-buffer overflow: preserve sentence boundaries

**Problem:** When `_userTypedSinceLastTerminator` exceeds `kUserBufCap`
(2048), the first half is erased with `erase(0, kUserBufCap / 2)`. This
can split a sentence in the middle, corrupting the harvest. The intent is
to discard old text, but erasing from the middle of a sentence produces
garbage corpus entries.

**Fix:** When overflow occurs, scan forward to find the next sentence
boundary (`'.'`, `'!'`, `'?'`) and erase up to and including that
character. If no boundary is found, discard the whole buffer (conservative
but safe).

**File:** `fcitx5-engine/src/xtype.cpp`

Find the overflow block in `keyEvent()`:

```cpp
if (_userTypedSinceLastTerminator.size() >= kUserBufCap)
    _userTypedSinceLastTerminator.erase(0, kUserBufCap / 2);
```

Replace with:

```cpp
if (_userTypedSinceLastTerminator.size() >= kUserBufCap) {
    // Discard up to and including the next sentence terminator in the first half,
    // so the remainder starts at a clean sentence boundary.
    size_t boundary = kUserBufCap / 2;
    auto& buf = _userTypedSinceLastTerminator;
    size_t pos = buf.find_first_of(".!?", boundary);
    if (pos != std::string::npos && pos + 1 < buf.size())
        buf.erase(0, pos + 1);  // erase through the terminator
    else
        buf.clear();             // no boundary found: discard all
}
```

No new unit tests needed — the existing corpus collector tests cover the
harvest path. Document in a comment that the buffer uses a rolling
strategy.

Commit: `fix(engine): typed-buffer overflow preserves sentence boundaries`.

## Step E6.3 — inference_client.cpp: fix hardcoded log path

**Problem:** Line 12 of `inference_client.cpp` opens a log file at
`/home/saint/Desktop/XType/fcitx5-engine/thread.log` — an absolute path
to the developer's machine. Any other user running XType would try to write
to a path that doesn't exist on their system.

**File:** `fcitx5-engine/src/inference_client.cpp`

Current:

```cpp
static FILE *ic_logfile() {
    static FILE *f = std::fopen("/home/saint/Desktop/XType/fcitx5-engine/thread.log", "w");
    return f;
}
```

Replace with:

```cpp
static FILE *ic_logfile() {
    static FILE *f = []() -> FILE* {
        // Write to the canonical XType user-data directory alongside fcitx5.log.
        const char* home = std::getenv("HOME");
        if (!home || !*home) return nullptr;
        std::string dir = std::string(home) + "/.local/share/xtype";
        std::error_code ec;
        std::filesystem::create_directories(dir, ec);
        return std::fopen((dir + "/inference.log").c_str(), "a");  // append, not overwrite
    }();
    return f;
}
```

Add `#include <filesystem>` and `#include <system_error>` to
`inference_client.cpp` if not already present (they should be — the engine
uses `std::filesystem` elsewhere).

Also change the open mode from `"w"` (overwrite on each engine start) to
`"a"` (append) so inference logs accumulate across restarts, consistent
with `fcitx5.log` behaviour in `xtype.cpp`.

Update `LogTail` in the settings app to also watch `inference.log` as a
fallback source if needed (optional: `LogTail` already falls back to
multiple log paths).

Commit: `fix(engine): move inference log to ~/.local/share/xtype/inference.log`.

## Step E6.4 — applyPrompt(): cap user description at source

**Problem:** `prompt_builder.cpp` documents that "userDescription is capped
at 1000 chars upstream (Session 19), so truncation should be rare." That
upstream cap does not exist anywhere — if a user types a very long
description, the prompt builder silently truncates token-by-token which is
slow and produces a cut-off sentence.

**Fix:** Cap `_cfg.user_prompt.description` when applying in `applyPrompt()`.
Do not add a cap in `config_loader.cpp` — the loader should faithfully
reproduce whatever the user wrote; the cap belongs at the point of use.

**File:** `fcitx5-engine/src/xtype.cpp`

In `applyPrompt()`, after `in.userDescription = _cfg.user_prompt.description`:

```cpp
// Cap user description at 500 chars to keep within prompt budget.
// The budget enforcer in buildSystemPrompt truncates at character level;
// truncating at a higher level here ensures the description ends on a
// word boundary.
static constexpr size_t kMaxDescLen = 500;
if (in.userDescription.size() > kMaxDescLen) {
    // Find the last space before the cap to avoid mid-word truncation.
    size_t cut = in.userDescription.rfind(' ', kMaxDescLen);
    in.userDescription.resize(cut != std::string::npos ? cut : kMaxDescLen);
    log_warn("user description truncated to fit prompt budget");
}
```

**Also fix the stale comment in `fcitx5-engine/src/prompt_builder.cpp`:**

Find the comment near the `userDescription` handling that says something
like `// userDescription is capped at 1000 chars upstream (Session 19)`.
Replace it with:

```cpp
// userDescription is capped at 500 chars in applyPrompt() before reaching here.
```

Remove the "Session 19" internal reference — it has no meaning in the codebase.

**Settings app:** In `PagePersonalisation.qml` `XInput` for description,
add a `maximumLength: 500` property (or display a character counter):

```qml
XInput {
    width: 280
    maximumLength: 500
    placeholderText: "…"
    text: Config.userDescription
    onEditingFinished: Config.userDescription = text
}
```

Commit: `fix(engine/settings): cap user description at 500 chars to protect prompt budget`.
