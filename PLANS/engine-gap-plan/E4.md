## Step E4.1 — Voice strength: proportional exemplar control

**What:** E3 implemented binary voice_strength (0 = no exemplars, non-zero
= all exemplars). This step makes it proportional: voice_strength of 50
includes 50% of exemplars, 25 includes 25%, etc.

The challenge is that `buildSystemPrompt` receives the full
`StyleProfile` and decides exemplar count during budget-based trimming.
To limit exemplar count independently of budget, we pass a trimmed copy.

**Approach:** In `applyPrompt()`, build a trimmed `PromptInputs` by
limiting the exemplar list before calling `buildSystemPrompt`.

`StyleProfile` doesn't expose a mutable exemplar list, so we bypass the
profile pointer and pass exemplars directly. Add a field to `PromptInputs`:

**File:** `fcitx5-engine/src/prompt_builder.h`

Add to `PromptInputs`:

```cpp
struct PromptInputs {
    // ... existing fields ...
    std::vector<std::string> exemplarsOverride;  // if non-empty, replaces profile->exemplars()
};
```

**File:** `fcitx5-engine/src/prompt_builder.cpp`

In `buildSystemPrompt`, replace:

```cpp
std::vector<std::string> exemplars;
if (in.includeExamples && in.profile && !in.profile->exemplars().empty()) {
    exemplars = in.profile->exemplars();
}
```

with:

```cpp
std::vector<std::string> exemplars;
if (!in.exemplarsOverride.empty()) {
    exemplars = in.exemplarsOverride;
} else if (in.includeExamples && in.profile && !in.profile->exemplars().empty()) {
    exemplars = in.profile->exemplars();
}
```

**File:** `fcitx5-engine/src/xtype.cpp`

In `applyPrompt()`, replace the voice_strength block from E3:

```cpp
// voice_strength: 0 = no exemplars, 100 = all, 1–99 = proportional slice.
if (_profile && !_profile->exemplars().empty() && in.includeExamples) {
    const auto& all = _profile->exemplars();
    size_t count = static_cast<size_t>(
        std::ceil(all.size() * std::clamp(_cfg.learning.voice_strength, 0, 100) / 100.0));
    if (count == 0) {
        in.includeExamples = false;
    } else if (count < all.size()) {
        // Take the first `count` exemplars (style_profile orders by representative quality).
        in.exemplarsOverride = std::vector<std::string>(all.begin(), all.begin() + count);
    }
    // count == all.size(): use default path (exemplarsOverride empty)
}
```

Add `#include <algorithm>` if not already present.

## Step E4.2 — Forget after days: corpus rolling window

**What:** `LearningConfig::forget_after_days` defaults to 0 (disabled).
When non-zero, entries in `corpus.txt` older than N days should be pruned.

The corpus format is plain-text lines (one sentence per line). There is
no embedded timestamp. The approach: when flushing to disk or when loading
on startup, filter out lines in a companion file `corpus_timestamps.txt`
whose timestamp exceeds the age limit. Keep the implementation simple:
timestamp file has one Unix timestamp per line, corresponding to each
corpus line.

**Alternative simpler approach (recommended):** Write a rotation: on each
flush, re-read `corpus.txt`, filter out lines older than N days using
`corpus_timestamps.txt`, write back the trimmed set. This avoids changing
the corpus format.

**File:** `fcitx5-engine/src/corpus_collector.h`

Add to the public interface:

```cpp
// Prune entries older than `days` (based on companion timestamps file).
// No-op if days == 0. Called from the flush thread.
static void pruneOldEntries(const std::string& corpus_path, int days);
```

**File:** `fcitx5-engine/src/corpus_collector.cpp`

Implement `pruneOldEntries()`:

```cpp
void CorpusCollector::pruneOldEntries(const std::string& corpus_path, int days) {
    if (days <= 0) return;

    namespace fs = std::filesystem;
    fs::path cp(corpus_path);
    fs::path tp = cp.parent_path() / (cp.stem().string() + "_timestamps.txt");

    // If no timestamp file, nothing to prune.
    std::error_code ec;
    if (!fs::exists(tp, ec)) return;

    // Read corpus lines and timestamps in parallel.
    std::ifstream cf(cp);
    std::ifstream tf(tp);
    if (!cf || !tf) return;

    std::vector<std::string> lines;
    std::vector<std::time_t> times;
    std::string line;
    while (std::getline(cf, line)) lines.push_back(line);
    while (std::getline(tf, line)) {
        try { times.push_back(static_cast<std::time_t>(std::stoll(line))); }
        catch (...) { times.push_back(0); }
    }

    // Prune lines whose timestamp is older than `days`.
    std::time_t cutoff = std::time(nullptr) - static_cast<std::time_t>(days) * 86400;
    std::vector<std::string> kept_lines;
    std::vector<std::time_t> kept_times;
    for (size_t i = 0; i < lines.size(); ++i) {
        std::time_t ts = i < times.size() ? times[i] : 0;
        if (ts == 0 || ts >= cutoff) {   // keep if no timestamp or within window
            kept_lines.push_back(lines[i]);
            kept_times.push_back(ts);
        }
    }

    // Write back atomically (temp + rename).
    auto write_atomic = [](const fs::path& dst, const auto& vec, auto to_str) {
        fs::path tmp = dst.string() + ".tmp";
        std::ofstream f(tmp);
        if (!f) return;
        for (const auto& v : vec) f << to_str(v) << '\n';
        f.close();
        std::error_code ec;
        fs::rename(tmp, dst, ec);
    };
    write_atomic(cp, kept_lines, [](const std::string& s){ return s; });
    write_atomic(tp, kept_times, [](std::time_t t){ return std::to_string(t); });
}
```

In the existing `flush()` method (the background thread), after writing
corpus lines, call:

```cpp
pruneOldEntries(_cfg.corpus_path_expanded, _cfg.forget_after_days);
```

`flush()` must have access to `forget_after_days`. Verify that
`CorpusCollector` stores the full `LearningConfig` (or at least
`forget_after_days`) — add it if not already stored.

**Timestamp writing:** In `CorpusCollector::record()` (or the flush path
where lines are written to corpus.txt), write corresponding timestamps
to `corpus_timestamps.txt`. Use the same atomic-write pattern.

## Step E4.3 — Per-app overrides: engine applies AppOverride

**What:** `XTypeConfig::apps` maps canonical program names to
`AppOverride`. The engine never applies these (E0 wires loading;
this step wires application). Three override fields are in scope:
`enabled`, `debounce_ms`, `num_predict`. `mode` maps to prompt_addendum.

**File:** `fcitx5-engine/src/xtype.h`

Add to the private section:

```cpp
    const AppOverride* currentAppOverride() const;  // nullptr if no override
```

**File:** `fcitx5-engine/src/xtype.cpp`

Implement:

```cpp
const AppOverride* XTypeEngine::currentAppOverride() const {
    auto it = _cfg.apps.find(_lastProg);
    if (it != _cfg.apps.end()) return &it->second;
    // Also try lowercased.
    std::string lower = _lastProg;
    std::transform(lower.begin(), lower.end(), lower.begin(), ::tolower);
    it = _cfg.apps.find(lower);
    if (it != _cfg.apps.end()) return &it->second;
    return nullptr;
}
```

**Applying `enabled`** — in `keyEvent()`, after the `isBlocked()` check:

```cpp
// Per-app override: if enabled is explicitly false, pass through.
if (auto* ov = currentAppOverride(); ov && ov->enabled.has_value() && !*ov->enabled)
    return;
```

**Applying `debounce_ms`** — in the debounce timer setup inside
`keyEvent()` (the printable-ASCII block):

```cpp
int debounceMs = _cfg.inference.debounce_ms;
if (auto* ov = currentAppOverride(); ov && ov->debounce_ms.has_value())
    debounceMs = *ov->debounce_ms;
uint64_t fireUs = fcitx::now(CLOCK_MONOTONIC) +
                  static_cast<uint64_t>(debounceMs) * 1000;
```

**Applying `num_predict`** — in `requestInference()`, before calling
`_inference.request()`, temporarily adjust the config copy:

```cpp
// Apply per-app num_predict override if set.
// InferenceClient uses its stored _cfg; we can't override mid-flight without
// an API change. Instead, pass num_predict as part of the context or add a
// per-request override. Simplest V1: update the client config before request.
InferenceConfig reqCfg = _cfg.inference;  // copy
if (auto* ov = currentAppOverride(); ov && ov->num_predict.has_value())
    reqCfg.num_predict = *ov->num_predict;
// Note: _inference.request() uses the stored _cfg, not reqCfg.
// To apply per-request num_predict, we need update_config before each request.
// This is safe because request() cancels any in-flight request.
_inference.update_config(reqCfg);
_inference.request(std::move(ctx), on_token, on_done, on_error);
// Restore global config after queuing so subsequent non-app requests are correct.
// update_config is thread-safe (mutex-guarded in inference_client.cpp).
_inference.update_config(_cfg.inference);
```

**Note on the restore pattern:** The update → request → restore sequence
is correct because `request()` copies `_cfg` into the pending `Req` at
the time of the call (before the worker thread runs it). However, if
`InferenceClient` reads `_cfg` in `execute()` rather than copying it at
request time, the restore could race. Verify by reading `execute()` in
`inference_client.cpp`; if `_cfg` is read in `execute()`, snapshot it
into the `Req` struct instead. Adjust accordingly — and document the
finding in 00-shared.md §7 if a design change is needed.

**Applying `prompt_addendum`** — in `applyPrompt()`:

```cpp
// Per-app prompt addendum (applied only when an app is active).
if (auto* ov = currentAppOverride();
    ov && ov->prompt_addendum.has_value() && !ov->prompt_addendum->empty()) {
    // Append to base within budget. Use remaining budget after base + user fields.
    in.base += "\n" + *ov->prompt_addendum;
}
```

**Note:** `applyPrompt()` is called at startup and on reload, when
`_lastProg` may be empty (no active app). The addendum should only apply
when an app is active. Move prompt addendum application to
`requestInference()` instead — rebuild the prompt per-request if the
addendum changes. This is a per-session design decision: for V1, applying
at `activate()` (when `_lastProg` is set) is sufficient since the prompt
is rebuilt on each reload. Document the limitation.
